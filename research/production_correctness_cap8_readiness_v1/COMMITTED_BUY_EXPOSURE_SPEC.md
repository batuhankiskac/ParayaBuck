# Committed BUY exposure

Canonical identity is `(account_id, client_order_id)` for a durable local order, with the same client ID used to deduplicate an exhaustive broker OPEN representation. Each nonterminal BUY contributes only `max(0, requested_qty - broker_filled_qty)` times a conservative available reference price. Local-only `submitting`, `submitted`, `partial_fill`, `pending_cancel`, and ambiguous rows remain commitments; cancellation is not release until authoritative terminal state is durable. If both views exist, count the larger valid remaining-notional estimate once. Broker-only manual BUYs also count; if a working order cannot be priced from broker notional/limit price, account mark or a durable matching reference, block new BUY admission rather than assume zero. Do not count working SELLs as negative commitment. The broker account's current position market value already includes filled BUY quantity.

The stored JSON for a dependent BUY during SELL phase is a contingent plan. It is not a broker order or a durable BUY order row, and the implementation always re-plans it after SELL resolution. It therefore does not consume committed headroom before submission. Slot reservations remain a separate count-based rule.
