## Conventions every module shares (frozen before any run)

* Execution is production **K** (`rule = "K"`), `leg = "2x"`, `cash_yield = "none"`; sizing is
  `fe_signals.sized_wants` and the E2 + early-re-entry state machine is production's
  (`fe_signals.r2_state`), except where an arm's own rule changes the vote or the early entry.
* **NaN semantics**, applied uniformly: a condition whose input is missing is **False** (no veto,
  no halving, no early entry), and a *multiplier* whose input is missing is the neutral value
  (1.00) rather than the arm's tilt factor. Warm-up windows are therefore neutral, never silently
  active.
* **Applicability** is the framework's own template rule
  (`if not np.isfinite(series).any(): raise NotApplicable`): a window is applicable when the extra
  series has at least one value in it. Where a series starts inside a window, the earlier sessions
  are neutral (documented per module). This is deliberately *more* coverage than some of the bank's
  `oos.evaluable` notes assumed: those notes read "no OOS window has FOMC dates / IEF starts 2002",
  but under a per-window rule `M1` (->1999), `M3`/`M4`/`M5` (->2026) and `GSPC_1957_1999` do carry
  the series and are applicable. The deviations and their reasons are recorded in each module
  docstring (`ib13`, `ib17`, `ib21`). The framework's `holdout_insufficient` verdict is therefore
  not triggered by any runnable arm.
* Arms that add a condition to the **early path's entry** (`ib01/C`, `ib05/C`, `ib21/C`, `ib34/C`)
  re-implement the state machine vectorised (`_r2_state_gated`, a last-event scan) because
  `fe_signals.r2_state` has no extension point. The clone is asserted **bit for bit** equal to
  `fe_signals.r2_state` (with the gate all-True) on the main window, an OOS window, an ETF window
  and a real bootstrap chunk — see `check_signals.py`.

## Data

`DATA_MANIFEST.json`: two hand-made series, `FOMC_DATES` (264 scheduled FOMC meeting announcement
dates, 1994-2026) and `FOMC_WEEK` (the dense per-calendar-day cycle index `w = floor((day - the
most recent meeting)/7 days)`), generated by `make_fomc_data.py` and registered in
`research/batch_screen/EXTRA_DATA.json` (the framework's own hand-registered-series path: no Yahoo
or FRED endpoint publishes meeting dates, and `extra.build` refuses non-downloadable series by
design). The plugin reads the dense index so that a bootstrap chunk replays the *drawn source
session's* cycle position, not the chunk's calendar labels. **Caveat:** the meeting table is
hand-transcribed from the Fed's published calendars; a wrong date shifts the parity for at most the
week after that meeting. Nothing else was downloaded or modified — `ib13`/`ib21` use the
already-registered FRED `DGS10` and Yahoo `IEF` series.

## Reproduce

```sh
R=~/.venvs/pb-research/bin/python
PYTHONPATH=. $R -m research.batch_screen.extra --verify        # 33 series, PASS
PYTHONPATH=. $R -m research.plugins_b1.make_fomc_data         # regenerates the two CSVs (hashes)
PYTHONPATH=. $R -m research.plugins_b1.check_signals          # 146 signal/dev checks
PYTHONPATH=. $R -m research.batch_screen.smoke --ideas ib01,ib05,ib09,ib13,ib17,ib21,ib30,ib34
PYTHONPATH=. $R -m research.batch_screen.smoke --ideas ib25   # NEEDS_KERNEL, by design
sh research/batch_screen/tests/run.sh                         # 100 framework tests
```

`check_signals.py` computes no performance number: it compares the added statistics against naive
reference implementations and the gated state machine against the engine, and checks every arm's
weight panel for finiteness/range plus a neutral-spec equality to K's own target series.
