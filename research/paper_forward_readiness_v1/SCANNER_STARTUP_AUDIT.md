# Scanner startup
Equity candidate path data/universe/equity_candidates.json, active path data/runtime/active_equity_universe.json, maximum age 36 h. Crypto active path data/runtime/active_crypto_universe.json, maximum age 12 h. Both require matching scanner config digest and have allow_static_fallback_trading=false. EngineRuntime constructor calls ensure_active_universes before subscriptions. Missing/stale snapshots cause provider refresh, two attempts with a 1 s pause; active files are atomically replaced only on success. Regular refresh uses configured 24 h cadence plus failure retry/backoff. A provider failure does not authorize static fallback trading.
A fresh clone with no runtime universe files can launch only if the online startup scanner succeeds; it is not independently ready offline. Before PAPER, an operator can run offline doctor to see REFRESH_NEEDED, then permit the normal online scanner during actual launch and require both active statuses success and /readyz 200 before treating trading as ready. This audit deliberately ran no scanner network call.
