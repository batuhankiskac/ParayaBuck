# Auto-start call graph
parayabuck web -> web.app.main -> FastAPI lifespan (web/lifespan.py) -> EngineManager.should_auto_start. With app.auto_start_engine true, paper mode, both credentials, and no security warning, lifespan schedules auto_start_engine. This means opening the server with PAPER credentials present starts the engine automatically; merely opening a browser against an already running server has no separate effect. Without credentials, no auto-start task is scheduled, /healthz answers 200, /readyz is 503 because trading is configured/expected.
Manager.start_engine creates EngineRuntime; its constructor ensures dynamic active universes (including provider refresh on missing/stale snapshots), constructs store/broker; start() first performs broker reconciliation before portfolio runtime construction, worker start, warmup, fresh account fetch, persisted rebalance resume, startup catch-up and final running state. Reconciliation failure halts and emits reconciliation_failure. A transient network failure leaves auto-start in starting with bounded retry. Missing/stale scanner snapshots trigger one retry after 1 second; failure leaves entry disabled and may stop construction when no enabled strategy has an active universe. /readyz only returns 200 when runtime.health().healthy for configured trading.
