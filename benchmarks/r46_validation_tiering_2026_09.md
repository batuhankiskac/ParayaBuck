## External metadata safety

`tests/conftest.py` owns the R46 registry and applies the `r46_deep` marker after collection. It checks every collected item in a registered R46 module against an exact `path::test_function` selector. A missing file, unknown collected selector, duplicate selector, or module/registry mismatch raises a pytest usage error. Full/default collection also compares collected selectors with the complete registry and reports stale selectors. A directly named narrow file invocation intentionally skips only that stale-completeness comparison so legitimate focused runs continue to work; unknown collected selectors still fail. No global test count is used as correctness logic.

## Risk analysis and native-code conclusion

The external registry can become stale only if a contributor bypasses full/default collection; broad collection fails closed, while direct focused invocations remain usable and still reject unknown collected R46 selectors. Path filters can over-trigger and are intentionally conservative; the weekly/manual deep schedule is the backstop for environment drift. The fast tier omits only explicitly marked deep items, and no test or verifier path was modified to make it pass. No process-local cache or mutable fixture sharing was added because safe sharing of attack-relevant replay state was not demonstrated.

The native-code conclusion is unchanged. The representative backtest engine remains sub-second in the existing benchmark evidence, while the strict R46 file-backed verifier consumes roughly four minutes. The measured bottleneck is verification cadence and immutable replay assurance, not the production backtest engine; Rust/C++ remains unjustified for this objective.
