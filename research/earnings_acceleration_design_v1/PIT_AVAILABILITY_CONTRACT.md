# Point-in-time availability contract

Candidate event time cannot precede the first verifiable public disclosure that contains all four EPS inputs, two price deflators, and split factors. For each raw document retain issuer, accession, form, item, accepted-at UTC, source URL, downloaded-at, content hash, and the first observed public availability if independently captured. `available_at = max(first-proven-public times of every required input)`. When only EDGAR acceptance exists, it is insufficient proof of first public content ([SEC FAQ](https://www.sec.gov/about/webmaster-frequently-asked-questions)); an explicitly conservative later availability rule would require pre-freeze evidence and would no longer be silently labeled the announcement strategy.

An Item 2.02/EX-99 release must be inspected for the precise earnings and share basis. Same issuer's later 10-Q facts become usable at their own proven availability, not at the 8-K time. EDGAR's Company Facts aggregate has no historical API-observation log; a current download does not prove an earlier API ingestion time. Calendar/fiscal-period-end fields never set `available_at`. In the 329 visible cached Item 2.02 rows through the canonical endpoint, seven have an official filed date one day *after* their UTC acceptance date; all 329 acceptance strings parse as timezone-aware. This is a concrete reason to retain both fields and never collapse them into one date. Paper day-2 start remains unresolved as to sessions and fill boundary. Thus no trade-eligibility timestamp is authorized.
