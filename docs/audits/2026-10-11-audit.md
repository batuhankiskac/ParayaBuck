### A1 — Entry latch (and signal-basis latch) is bypassed for the persisted deferred BUY on both decision paths
- Round 1 · confidence: confirmed (repro ran; `_submit_deferred_buys` observed invoked with the latch set) · **VERIFIED (coordinator read code; also found independently as R5D-1)**
- Location: src/parayabuck/runtime.py:2249-2254 (`_advance_portfolio_rebalance.submit_buys`), src/parayabuck/runtime.py:3150-3153 (latch computed for the decision), src/parayabuck/runtime.py:3584-3603 (latch computed for the catch-up) → src/parayabuck/portfolio/runtime_service.py:1054 (`_process_closed_bars`) and :788 (`startup_catch_up`)
- Problem: `EngineRuntime._advance_portfolio_rebalance` is the only caller that computes `submit_buys` (breaker + `_reconcile_failed` + `_entry_risk_latch` + `_market_entry_halts`) and passes `submit_deferred_buys`. Inside `PortfolioRuntime`, both `_process_closed_bars` and `startup_catch_up` call `self.advance_rebalance(account=account)` and rely on the default `submit_deferred_buys=True` (runtime_service.py:1584), even though the runtime hands them a non-None `entry_latch`. The E14 invariant ("a deferred BUY of a two-phase rebalance is an entry, so a latched or halted market keeps it deferred") therefore holds only for the trade-update/startup-resume wrapper, not for the two paths that actually decide.
- Scenario: repro `repro_latch_bypass.py` / `repro_decision_path_latch.py` (ran, throwaway). A persisted rebalance at `REBALANCE_PHASE_BUY_READY` plus `entry_latch="portfolio_drawdown_halt"` (or `"signal_adjustment_unverified"`, which trips whenever the hourly provider verification fails): `startup_catch_up` and `process_closed_bars` both call `_submit_deferred_buys`, advance the phase to `buy_pending`/`rebalance_complete` with the latch set. On startup the drawdown latch is restored from the persisted incident (`_restore_persistent_state`), `_resume_startup_rebalances` correctly withholds it, and `_run_startup_catch_up` (whose readiness gate does not include the latch) then submits it anyway.
- Fix: make the latch gate the flag the runtime already computes: have `process_closed_bars`/`startup_catch_up` pass `submit_deferred_buys=entry_latch is None` (or accept an explicit flag and have `runtime.py:2249`'s predicate feed it at 3150/3584) instead of relying on the `True` default.

### B1 — `working_buy_orders()` crashes with TypeError on a working notional BUY that has not filled
- Round 1 · confidence: confirmed (repro ran under `.venv/bin/python -I`). · **VERIFIED (coordinator read code)**
- Location: src/parayabuck/execution/alpaca.py:289-294 (sole production consumer: src/parayabuck/portfolio/runtime_service.py:2189 `_size_buys_to_safe_capacity`, also reached via `current_buy_capacity()` at :2294)
- Problem: `remaining_notional` is guarded by `notional is not None and (filled == 0 or average is not None)`, but the expression still evaluates `filled * float(average)`. When a working NOTIONAL BUY has no fill, Alpaca returns `filled_qty=0` and `filled_avg_price=None`; the `filled == 0` disjunct makes the guard pass and `float(None)` raises `TypeError` before the multiplication.
- Scenario: an operator's manual $500 notional BUY of MSFT works on the shared PAPER account → the session-close decision that must BUY QLD calls `_size_buys_to_safe_capacity` → TypeError → the decision is deferred/re-planned on every advance until that order fills (SELL-only legs unaffected); `ops capacity`/dashboard capacity panel also errors out. Repro: fake OPEN order `qty=None, notional=500, filled_qty=0, filled_avg_price=None` → `CRASH: TypeError float() argument must be a string or a real number, not 'NoneType'`. The bot's own orders are qty-based (`notional=None`), which is why the suite never hit it.
- Fix: `filled_notional = filled * float(average) if average is not None else 0.0`, then `remaining_notional = max(0.0, notional - filled_notional) if notional is not None else None` (same shape, no crash, same remaining-notional semantics).

### R5B-1 — `apply_trade_update` books non-finite fill facts, wedging ownership at `inf` with no auto-recovery
- Round 5 · confidence: confirmed (repro ran: inf-owned + unhealable, NaN-fee row drop with cumulative advanced, zero/negative-price fills booked)
- Location: src/parayabuck/portfolio/runtime_repository.py:1116 (`apply_trade_update`; order update :1206-1219, fill insert :1230-1247)
- Problem: `cumulative_filled_quantity`, `average_fill_price`, and `fee` are never validated as finite. `float("Infinity")`/`"1e999"` from a hostile broker string parses straight through `_parse` into this sink.
- Scenario: stream delivers `filled_qty=inf, avg=100` → order row stores `cumulative=inf`, `owned_quantities` returns `{'QLD': inf}` forever (a later legit `cum=10` computes `max(inf,10)=inf`, delta `max(0,10-inf)=0`, so it can never heal); every later pure-BUY decision then raises in `_committed_buy_notional` (`remaining = 10-inf`, non-finite → `ValueError`, runtime_service.py:2142) and halts. Zero/negative `average_fill_price` books fills at price `0`/`-5`.
- Fix: reject non-finite/negative cumulative and non-positive average (when delta > 0) and non-finite observed fees (coerce to unobserved) at the top of `apply_trade_update`, before any write.

### R5B-2 — Non-finite `last_equity`/`equity` sails through the snapshot and silently disables the entry-risk latch

### R5D-1 — Persisted deferred BUY submits on the decision/catch-up path despite an entry/signal-basis latch

### A2 — A partial SIP session-close fallback success drops the other symbols' decision input for that session
- Round 1 · confidence: confirmed (repro ran)

### C-01 — Foreign partial sell at a known split ratio is audited as a reverse split
- Round 1 · confidence: confirmed (repro ran the real classifier and the branch code path)
- Location: src/parayabuck/portfolio/ownership_rebase.py:215-231 (with the row written at src/parayabuck/portfolio/runtime_repository.py:1598-1625)
- Problem: In `classify_share_change`, the `broker < owned` branch classifies by ratio *before* consulting the cost basis, so any share decrease that lands on a `KNOWN_SPLIT_RATIOS` value is returned as `SPLIT`. `reconcile_broker_quantity` then writes `kind=SPLIT_REBASE_KIND` ("split_rebase") into `portfolio_ownership_adjustments` and the reason reads "N-for-1 reverse split". A foreign sell whose leftover fraction is exactly 1/2, 1/4, 1/3, 1/5, 1/8, 1/10 (or 1:2, 1:3, 1:4, 1:5) of the position is indistinguishable from a real reverse split on the audit trail, even though the broker's unchanged `avg_entry_price` proves no corporate action occurred.

### E01 — Backtest completeness gate requires the SPY benchmark bar; the live runtime explicitly does not
- Round 1 · confidence: confirmed (repro ran)
- Location: `src/parayabuck/backtest/portfolio_engine.py:984-999` (gate) + `:1311-1358` (`_effective_observation_symbols`); `src/parayabuck/backtest/universe.py:101,109,111` (`observation_set`/`pinned_symbols` = *all* configured symbols); contrast `src/parayabuck/portfolio/runtime_service.py:463-474` (`_required_symbols`) and `src/parayabuck/portfolio/equity_leveraged_trend.py:76-79` (`decision_symbols` → `('QQQ','QLD')`)
