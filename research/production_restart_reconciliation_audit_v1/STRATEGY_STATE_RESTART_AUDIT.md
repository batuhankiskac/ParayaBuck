# Strategy state on restart

Current configured product names are loaded through \`product_strategy_from\` in \`EngineRuntime.__init__\` (\`runtime.py:279-301\`); the audit did not inspect economic outcomes. Portfolio runtime restores the last decision timestamp by account, configuration digest, and market (\`portfolio/runtime_service.py:338-341\`), while the engine mirrors decision watermarks (\`runtime.py:2382-2408\`). The crypto 96-hour cadence is a declared strategy parameter (\`crypto_low_variance.py:164-180\`), and held-name hysteresis uses the current broker holdings in \`PortfolioContext\` plus current rank/eligibility (\`crypto_low_variance_hysteresis.py:63-105\`), not a separate volatile retained-name list.

Equity cadence likewise uses persisted \`latest_decision_timestamp\`; startup catch-up refuses if any prior decision exists for the same deployment (\`runtime_service.py:446-550\`). Rebalance phase/order rows are persisted before submission. Equal market data and equal broker/local state should therefore produce the same cadence and target inputs. The audit's existing restart tests verify representative cases, but it did not run a full paired uninterrupted-versus-restart event stream for every strategy and every crash point.
