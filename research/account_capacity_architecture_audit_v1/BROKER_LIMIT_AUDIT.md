# Broker and API limit audit

Status: `NO_BROKER_REQUIREMENT_FOR_SIX_FOUND` (documentation review, 2026-09-22). This is not a claim that every account entitlement or unpublished limit has been tested. No credentialed call or broker order was made.

## Integration actually used

`src/parayabuck/execution/alpaca.py:81-120` constructs the Alpaca execution boundary. `src/parayabuck/execution/alpaca_orders.py:165-225` sends quantity-based market orders with DAY time in force for equity and GTC for crypto. It checks the broker asset's quantity increment and minimum size/notional first, rejects a second open order for the same symbol, and recovers ambiguous submissions by client order ID. The account-wide six-slot gate is repository policy in `config/settings.yaml:182`, mapped through `src/parayabuck/execution/portfolio.py:112-125` and applied at `:266-306`; it is not an Alpaca response field.

## Current published broker mechanics

| Question | Official documentation and architectural implication |
| --- | --- |
| Maximum simultaneous positions | The reviewed Trading API order, position, account, fractional, and crypto pages state no six-position or other general account position-count ceiling. This is an absence-of-documentation finding, not proof that no account-specific restriction could exist. [Orders](https://docs.alpaca.markets/us/docs/orders-at-alpaca), [positions](https://docs.alpaca.markets/us/docs/working-with-positions), [account](https://docs.alpaca.markets/us/docs/account-plans). |
| Maximum open orders | No general six-order ceiling was found in those Trading API pages. Alpaca does reject some overlapping or oversized closing-order situations. The repository's one-open-order-per-symbol rule is separate and stricter for its ordinary portfolio order gateway. [Orders](https://docs.alpaca.markets/us/docs/orders-at-alpaca). |
| Buying power | An opening order must pass a buying-power check. Open long-buy orders reserve buying power until filled or canceled; closing sells do not replenish it until execution. This can affect a sell-then-buy rebalance, but it is a value constraint rather than a six-name limit. [Orders, Buying Power](https://docs.alpaca.markets/us/docs/orders-at-alpaca). |
| Fractional equity | Eligible US equities can be bought in fractional shares; Alpaca documents $1 as the smallest fractional equity purchase, DAY time in force, and asset-specific fractionability. The repository uses quantity, not notional, and still floors to its asset rules, so fractionability does not guarantee every proposed tiny order executes. [Fractional Trading](https://docs.alpaca.markets/us/docs/fractional-trading). |
| Crypto | The Trading API accepts fractional crypto quantity or notional orders with GTC/IOC; crypto is non-marginable and non-shortable. Asset minimum size/increment still applies. The documented $200,000 maximum is **per crypto order**, not a maximum number of holdings. [Crypto Spot Trading](https://docs.alpaca.markets/us/docs/crypto-trading). |
| Rate limit | Alpaca's Trading API support page says 200 requests/minute/account and HTTP 429 on excess. It was published in 2022 and may be account-specific or revised; actual entitlement should be checked from the current account/headers before any future migration load test. Even the published number does not define six positions. Do not conflate this retail Trading API with Alpaca's partner Broker API, whose rate limits are separately configured and unpublished. [Trading API support](https://alpaca.markets/support/usage-limit-api-calls), [Broker API rate limits](https://docs.alpaca.markets/us/docs/broker-api-rate-limits). |
| Account type / restrictions | Account buying power, blocked status, and shorting entitlement can constrain orders; none supplies a six-position rule. The system is long-only. Avoid using historical PDT assumptions as a position-count rationale, particularly given Alpaca's 2026 PDT/DTBP deprecation notice. [Trading Account](https://docs.alpaca.markets/us/docs/account-plans), [2026 changelog](https://docs.alpaca.markets/us/changelog/2026-06-03-pdt-651df23). |

**Conclusion:** Alpaca's documented restrictions are order-, instrument-, account-, and request-rate-specific. Six is an internal account policy. Higher counts would increase order and status traffic and require operational validation, but the published broker material does not mandate six.
