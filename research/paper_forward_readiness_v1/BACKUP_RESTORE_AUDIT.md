# Backup and restore
Config: data/backups, retention 7 days. backup_database uses SQLite online backup, integrity verification before publication/pruning, fsync and collision-safe filenames; tests/test_backup.py covers WAL, uncommitted exclusion, corrupt backup, retention, collision and durability errors with tmp_path.
Operator: run parayabuck backup under the deployment service identity; capture the returned filename. Run parayabuck backup --verify-only PATH. Stop the engine before a restore drill. Copy the verified backup to a NEW separate path, for example /tmp/parayabuck-restore-check.sqlite3; run sqlite3 /tmp/parayabuck-restore-check.sqlite3 'PRAGMA integrity_check;'. Compare schema and expected rows. Never overwrite data/runtime/parayabuck.sqlite3 while a process uses it; retain current DB and sidecars for forensic recovery. No real backup or restore was performed.
