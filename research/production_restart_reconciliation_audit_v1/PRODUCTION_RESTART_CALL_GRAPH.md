# Production restart call graph

Baseline: \`main@af7225e1952c20a81f7d22d4f8d98126f02e27b3\`. This graph follows the configured web manager, not a test-only construction.

1. \`src/parayabuck/web/managers/engine.py:480\` constructs \`EngineRuntime\`. \`src/parayabuck/runtime.py:212\` validates mode, loads configured universes/strategies, opens \`SQLiteStore\`, \`ExecutionLedger\`, and \`PortfolioStateRepository\` (:302-309), and constructs \`AlpacaBroker\` with repository ownership/open-order callbacks (:311-335). No broker order is submitted by this construction.
2. \`EngineRuntime.start\` → \`_start_impl\` (:861-910) verifies mode/live proof and calls \`broker.reconcile()\` before strategy workers exist. \`AlpacaBroker.reconcile\` (:774) delegates to \`ReconciliationService.reconcile\` (\`execution/alpaca_reconciliation.py:391\`).
3. Reconciliation calls \`broker.account()\` (:403) → \`AccountService.account\` (\`execution/alpaca_account.py:130\`) → Alpaca \`get_account\`, \`get_all_positions\` (:133, :154). It classifies ledger/repository ownership, updates persisted account peak, and builds cash/equity/position snapshot (:225-251).
4. It next retrieves FILL activities through \`AlpacaClient.request("GET", "/account/activities/FILL", ...)\` (\`alpaca_reconciliation.py:122-283\`), reads ledger ownership, compares broker and local quantities (:411-465), attempts stale ownership/exit/protection repair (:466-594), then compares local nonterminal portfolio order IDs with **exhaustive** broker OPEN orders (:597-617).
5. \`EngineRuntime._start_impl\` validates all seven reconciliation buckets and halts on any drift or error (:910-947). Only then it builds \`PortfolioRuntime\` instances (:949-1014). \`PortfolioRuntime.__init__\` reads latest decision timestamp and starts a persisted session (\`portfolio/runtime_service.py:338-341\`).
6. \`EngineRuntime._restore_persistent_state\` (:2327) restores persistent safety incidents, today's loss counter, and decision watermarks. Threads start only after this (:1051-1088), with \`_warming_up=True\`; \`_warmup\` seeds market history.
7. After warmup, \`_start_impl\` obtains a new broker account snapshot, publishes it, persists risk (:1110-1118), resumes persisted rebalances (:1122; helper :2481), and runs startup catch-up (:1126; helper :3520). \`PortfolioRuntime.startup_catch_up\` (:446) checks prior decision/holdings and routes to normal decision path. Thereafter normal bar decisions use \`_decision_loop\` (:2807) and \`_process_portfolio_timestamp\` (:3098).

Important ordering: reconciliation itself can issue protective stop orders at \`alpaca_reconciliation.py:571-595\` (when configured to manage the position). The audit did not invoke this path against a real broker. The decision worker exists before warmup completes, but its decision gates include warming/readiness; first intentional startup decision is after the fresh account/risk pass.
