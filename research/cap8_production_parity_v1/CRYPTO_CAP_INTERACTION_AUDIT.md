# Crypto cap interaction

Production `config/settings.yaml:182` sets `max_crypto_positions: 2`, `max_crypto_exposure_pct: 0.10`, and `max_crypto_position_pct: 0.05`. `RiskLimits` requires the crypto count not exceed the global count; `portfolio_risk_limits_from_config` preserves all three (`execution/portfolio.py:112-125`). Overlay uses `maximum_crypto_positions` for current-market crypto and `maximum_positions` for the global account (`portfolio.py:266-307`). Cap 8 changes only the latter. The frozen migration specification changed only `maximum_positions`; no treatment authority authorizes more crypto positions or different sleeve/name caps. The pure-BUY defect is cross-market and can be triggered by marked crypto exposure with equity openings; the crypto cap does not cure it.
